## OWASP GenAI LLM Top 10 (2026 Edition) Mapping to NEXUS AI Controls

| 2026 ID | Risk Category (and 2025 Shift) | Threat Vector in Enterprise RAG / Agents | Implemented Control in NEXUS AI |
| :--- | :--- | :--- | :--- |
| **LLM01:2026** | **Prompt Injection** (Rank #1 in 2025) | Direct user jailbreaks or **Indirect Prompt Injection** embedded inside uploaded PDFs/DOCX policies attempting to hijack system instructions or exfiltrate secrets. | `PromptInjectionGuard` scans both user queries and retrieved document chunks; untrusted document content is wrapped in strict `<untrusted_document_evidence>` XML delimiters; instructions found inside documents are stripped/flagged and never executed as tool calls. |
| **LLM02:2026** | **Sensitive Information Disclosure** (Rank #2 in 2025) | PII, API keys, or cross-tenant confidential documents exposed in model outputs or observability logs. | `SensitiveDataRedactor` scrubs API keys, JWTs, SSNs, and secrets from prompts, outputs, and telemetry logs; strict `organization_id` + workspace RBAC pre-filtering before context assembly. |
| **LLM03:2026** | **Excessive Agency** (Moved up from #6 in 2025) | Agents invoking destructive tools, executing arbitrary code/SQL, or taking consequential actions without human oversight. | Zero shell/SQL/code execution tools. `ToolRegistry` enforces per-tool RBAC roles (`Owner`/`Admin`/`Manager`/`Member`), strict Pydantic JSON schemas, idempotency keys, and mandatory `HumanApprovalNode` interrupts for state-changing tools (`create_internal_task`, `generate_report` publish). |
| **LLM04:2026** | **Supply Chain** (Was #3 in 2025) | Compromised dependencies or unverified model endpoints. | Pinned dependency lockfiles, verified provider endpoints, SHA-256 checksums on all ingested documents and evaluation datasets. |
| **LLM05:2026** | **Data and Model Poisoning** (Was #4 in 2025) | Malicious or corrupted documents poisoning the knowledge base index. | Document provenance tracking (`uploaded_by`, `sha256_hash`, version history), quarantine flagging on suspicious instruction density, and admin-controlled document versioning/deletion. |
| **LLM06:2026** | **Unbounded Consumption** (Moved up from #10 in 2025) | Denial-of-wallet attacks, runaway agent loops, oversized file uploads, or context-window exhaustion. | Configurable hard caps: max upload size (25 MB), token budget limit (`max_context_tokens=6000`), agent `max_steps=12`, `max_tool_calls=6`, per-user/per-org rate limiting, and request timeouts. |
| **LLM07:2026** | **Misinformation** (Moved up from #9 in 2025) | Unverified hallucinations presented as authoritative company policy or fabricated numerical metrics. | Mandatory `EvidenceVerificationNode` and `CitationValidator`; deterministic abstention when evidence score falls below threshold; all spreadsheet math computed deterministically via Pandas (`DataAnalyticsEngine`). |
| **LLM08:2026** | **Hidden Context Exposure** (Renamed & broadened from System Prompt Leakage, #7 in 2025) | Exfiltration of system prompts, internal routing rules, or hidden retrieval metadata. | Output filter blocks system prompt disclosure patterns; internal chain-of-thought is never exposed to clients (only sanitized workflow step transitions are streamed). |
| **LLM09:2026** | **Vector and Embedding Weaknesses** (Was #8 in 2025) | Cross-tenant vector similarity bleed, approximate HNSW post-filter starvation, or embedding inversion. | Mandatory tenant & workspace metadata pre-filtering in SQL prior to vector distance ranking; PostgreSQL RLS policies on `document_chunks` and `document_embeddings`. |
| **LLM10:2026** | **Improper Output Handling** (Was #5 in 2025) | Unsanitized LLM output rendered as XSS in frontend or passed directly into downstream interpreters. | Strict Pydantic output schema validation, HTML/script tag sanitization on rendered markdown/citations, and parameterized SQL queries everywhere. |
